# A+B+C 文件级缺陷定位论文大纲

本文以 **A 原报告语义检索＋B 功能推测语义检索＋C 代码证据重排** 为主线。方法的公式、版本和运行入口统一引用[方法定义](main-method.md)，不再将 BM25 融合或旧 Max C3 写成当前完整方案。早期详细草稿及文献笔记保存在[历史 C3 大纲](paper-outline-c3-history.md)。

## 研究问题与方法贡献

1. **两类查询能否提供互补候选？** A 保留原报告线索，B 仅根据报告生成功能描述，两路独立检索同一修复前源码。
2. **怎样在固定候选预算下利用互补信息？** 对 A50∪B50 做归一化分数融合与源码结构匹配，保留 50 个文件；分别评价候选覆盖与初排排序。
3. **怎样把候选转化为有效代码证据？** 每文件取 A 最优块、B 补足至最多三块；C 结合逐块最大 logit、联合文档 logit 与初排先验，只调整 Max C 前十。
4. **改善来自哪里，能否跨项目和数据集复现？** 通过模块消融、机制分析、失败归因和冻结后的项目验证回答，明确已有样本被反复观察的限制。

这些是需要论证的具体设计；不直接宣称首次双路检索、结构匹配或现成重排器本身构成创新。AST 分块是基础表示，LoRA、8B 和 Agent 是独立扩展，不能将其成绩混入当前小模型 C。

## 方法章节必须写清的内容

- 初排参照：`p=.5N(A)+.5N(B)+.5E`；候选为 A50∪B50 中得分最高的 50 个文件。
- C 参照：`s=.75z+.25u+4p`；只调整逐块 Max C 的前十，保持前十集合与尾部顺序。
- 原 Python 结构版本 `ab_structure_v1` 与多语言 `structure_ast_v2` 必须分别标注。
- 功能推测参与 B 检索与选块，其文本不直接输入 C；联合文档不含标签、补丁或检索分数。
- `configs/baselines/current.json` 只是 A+B 子阶段注册，不代表完整研究只含 A+B；C 由实验协议冻结。
- 系数是参照设置，不能写成已证明跨数据集最优；现有完整实验入口依赖冻结的历史产物。

## 结果组织与证据边界

完整 500 条 A+B+C 的 MAP@10 为 0.691051、Top1 为 66.0%、Top10 为 93.2%；同批新候选＋原 Max C 的 MAP@10 为 0.648499。该组含既往开发样本，不能写成独立盲测。新候选相对旧候选＋新版 C 的额外 MAP 差值仅 0.000879，未显著。

多语言结构下的 GHRB/SWE 项目验证单独成表：共享开发系数在 SWE 有改善，在 GHRB 未复现收益，不能由此宣称统一最优。SWE 留出项目此前也被观察过。精确系数 4 的敏感性分析是事后分析，不是新的独立选参验证。

历史模块消融、旧 RRF、旧 Max C3 与最新完整方法采用的协议不同。已有结果可展示方法演进，但不能把不同批次拼成同条件消融表。完整主线仍需以对应冻结版本和同样本评分重建最终论文的公平对照。

## 写作与补充工作

优先固定论文所用结构版本和候选协议，并整理同条件 A、B、A+B、A+B+C 主表与消融表。成本应分开报告生成、编码、检索、逐块/联合重排和缓存重放，不能将增量补算时间当成端到端时间。

跨数据集推广需要提前冻结候选系数与选择规则，并在未参与本轮分析的项目上验证。完整复现包还需单独提供允许分发的逐例结果与来源说明；`results/` 本地资产不随代码仓库上传。
