# BM25 与 AST 的文件级 RRF 融合

当前实验复用已完成的 BM25 与 AST 结果，以文件名次计算等权 RRF：

`S(f) = 1 / (60 + BM25文件名次) + 1 / (60 + AST文件名次)`

文件在某路没有匹配结果时，该路贡献为 0，不补造尾部名次。名次从 1 开始，同分按相对文件路径升序。这里的 60 是 RRF 平滑常数，评价截断仍为 @10。AST 文件名次由已有 Max Chunk 聚合产生；不对 Chunk 名次融合，也不直接相加 BM25 与余弦原始分数。

## 输入范围与复用

旧 BM25 批次只保存了前 10 名，直接与完整 AST 排名融合会混入两路检索深度不一致的影响。本入口使用旧结果记录的索引和原始查询，从**已有 ES 索引**补取全部匹配文件，并核对：

- 索引归属、修复前提交、配置指纹、候选文件路径与源码哈希；
- 补取后的匹配总数、前十名次、前十分数及 @10 指标与旧结果一致；
- 两路报告清单、顺序、原始正文、候选、标签和缺失候选标签一致；
- AST 排名完整覆盖候选文件且没有重复文件。

补取仅查询已有索引，不建库、不编码、不下载数据。如果旧索引不在当前 ES 中，先按 README 的 BM25 流程运行同样的报告，再传入新批次目录；不要去掉校验或补造后续名次。该入口要求输入批次全部成功，发现缺失、失败或不一致会报错并保存失败状态。

## 运行

先按 README 完成 BM25 和 AST 批次。新入口独立于原比较入口；原 `run_vector_batch.py --fusion` 仍是既有的语义多路融合控制，不表示 BM25＋AST。

```bash
# 使用原 AST 或候选前缀 96 配置生成语义结果
python -B scripts/retrieval/run_vector_batch.py --config configs/experiments/ast_prefix96_candidate.json
# 下条命令中的两个目录标记需替换为实际日志打印的批次目录
python -B scripts/retrieval/fuse_rankings.py --bm25-run BM25_BATCH_DIRECTORY --semantic-run ast96=SEMANTIC_BATCH_DIRECTORY
```

`--semantic-run LABEL=PATH` 可重复指定，对多个语义对照分别与同一份 BM25 做双路 RRF；不会把它们一起拼成三路。目录包含空格时，对整个 `LABEL=PATH` 参数加引号。`--route` 默认 `blagent_ast`，也支持已有其他语义路线。`--rrf-constant` 默认 60。本轮没有搜索权重、常数或截断深度。

本次 44 条对比的完整命令（Windows / Ubuntu 项目根目录均可用，需先持有这些批次）：

```bash
python -B scripts/retrieval/fuse_rankings.py --bm25-run results/bm25/batches/swe_bench_formatted_test_20261015_214827_234722 --semantic-run ast64=results/vector/batches/swe_bench_formatted_test_20261025_095905_736417 --semantic-run ast96=results/vector/batches/swe_bench_formatted_test_20261025_190040_327947 --rrf-constant 60
```

数据、模型和 ES 配置仍使用原配置文件，不在新入口中写死路径或地址。运行代码位于 `src/bug_localization/hybrid.py`，复用 `vector.rrf`、`bm25.ranking_metrics`、`batch.aggregate_results`，不改变原检索和评价算法。无需新增依赖。

## 本次结果（2026-10-25）

范围：SWE-bench 格式化版 `psf/requests` 同一份 44 条报告。AST 字符预算 1500、总输入 512 tokens，两个对照的结构前缀预算分别为 64 / 96。BM25 使用全部匹配文件，AST 使用完整候选文件排名；RRF 等权、常数 60，评价 @10。

| 方法 | MAP@10 | MRR@10 | Top-1 | Top-5 | Top-10 | MeanRecall@10 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| BM25 | 0.4596 | 0.5080 | 0.2727 | 0.8182 | 0.9318 | 0.8632 |
| AST，前缀64 | 0.6297 | 0.6526 | 0.4773 | 0.8636 | 0.9545 | 0.9418 |
| AST，前缀96 | **0.6351** | **0.6636** | **0.5000** | 0.8636 | 0.9545 | 0.9418 |
| BM25＋AST64 RRF | 0.5899 | 0.6281 | 0.4318 | 0.8636 | **1.0000** | **0.9669** |
| BM25＋AST96 RRF | 0.5921 | 0.6327 | 0.4318 | 0.8636 | **1.0000** | **0.9669** |

两组融合各 44/44 成功，无失败。输入三个基线的全部指标保持不变。独立重算 88 份融合排名、逐文件 RRF 分数、逐报告评价及汇总全部通过，CSV 的 16,718 行与对应 JSON 排名逐项一致。测试共 61 项通过。没有重新编码模型或重建索引。

RRF 相比 AST96 的 MAP 下降 0.04293、MRR 下降 0.03094，Top-1 从 22/44 降至 19/44；Top-10 从 42/44 提至 44/44。这里的 100% 表示每个报告至少一个真实文件进入前十，不表示所有真实文件都被找全；MeanRecall@10 为 96.69%，原来一个缺失候选标签仍保留。

逐报告 AP 相比各自 AST 均为 15 胜、18 平、11 负；虽改善样本更多，部分大幅退化使平均指标下降。以报告为单位 bootstrap 20,000 次（seed=20261025），RRF96−AST96 的 MAP 描述性 95% 区间为 `[-0.1266, 0.0345]`，MRR 为 `[-0.1273, 0.0587]`。样本同属一个项目、快照相互关联且此前已观察，不能作独立最终测试或跨项目显著性结论。

前两例补足语义路线的前十漏召回；后两种退化说明，BM25 对某些真实文件排序较低时，等权 RRF 会压低原本准确的语义结果。因此本轮融合有助于扩大前十候选覆盖，但未超过 AST 的前排质量，不自动替换现有默认排序。权重或常数调整需在预先固定的验证集另行比较，本轮没有按这些结果继续搜索。

## 不使用名次的路线投票（2026-10-25）

按用户指定的定义：**每条路线对同一文件最多投 1 票**。本轮分别比较 BM25＋AST64、BM25＋AST96，不把两个 AST 对照重复计入同一次融合。

`V(f) = I(f 出现在 BM25 候选中) + I(f 出现在 AST 候选中)`

两路都出现得 2 票，只在一路出现得 1 票；不使用原始名次或相似度计算票数。同一路重复文件先去重。完全不考虑输入名次时使用全部候选；另测两路各取 Top-10 后的投票。Top-10 的候选选取本身使用输入顺序，但选定后，内部名次不提供任何票数加成。未进入任一路候选的文件不输出。

### 同票问题

纯票数只能确定并列组，不能给组内文件排出相关性先后。本实现按文件路径固定展示同票文件，**没有用输入名次或原始分数破同票**。输出的 `rank` 只是该展示规则下的位置，`tie_rank_start/end` 才描述票数能确定的并列范围。

为避免把文件名排序的影响当成检索能力，另外精确计算每个同票组内部均匀随机排序时，原始 @10 指标公式的期望。它不是另一次模型实验或随机模拟，也不替代路径排序的真实排名记录；真实标签仅用于评价，不用于计票或排列。期望公式已通过小规模同票组的全部排列枚举验证，并覆盖 Top-10 在同票组中间截断和缺失候选标签。

### 44 条报告的结果

全量投票中，3,361 个报告—候选文件实例里，3,274 个（**97.41%**）都得 2 票。每条报告最高票组平均 **74.41** 个文件，范围 32–122，几乎无法区分文件。

两路各取 Top-10 后，平均仍有 **5.82** 个文件同时得到 2 票（范围 2–8）；44/44 条报告的前十都有同票。AST64 与 AST96 的本轮投票汇总指标相同，不代表全部候选集合相同：两者有 42/44 条报告的 Top-10 文件集合相同，另外两条集合不同但本轮指标相同。

以下主表展示可复查的固定路径展示排序，及同样输入深度下的 RRF 对照（以 AST96 为例）：

| 方法 | 每路候选范围 | MAP@10 | MRR@10 | Top-1 | Top-5 | Top-10 | MeanRecall@10 |
| --- | --- | ---: | ---: | ---: | ---: | ---: | ---: |
| AST96 原排名 | 全量 | 0.6351 | 0.6636 | 0.5000 | 0.8636 | 0.9545 | 0.9418 |
| RRF | 全量 | 0.5921 | 0.6327 | 0.4318 | 0.8636 | 1.0000 | 0.9669 |
| 纯投票，同票按路径展示 | 全量 | 0.0269 | 0.0448 | 0.0000 | 0.0909 | 0.2500 | 0.1430 |
| RRF（同候选池对照） | Top-10 | 0.5929 | 0.6348 | 0.4318 | 0.9091 | 1.0000 | 0.9683 |
| 纯投票，同票按路径展示 | Top-10 | 0.4101 | 0.4388 | 0.1818 | 0.8182 | 0.9773 | 0.9418 |

这两种投票大量依赖同票展示顺序，应同时阅读均匀随机同票排序的精确期望：

| 投票候选范围 | 期望 MAP@10 | 期望 MRR@10 | 期望 Top-1 | 期望 Top-5 | 期望 Top-10 | 期望 MeanRecall@10 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 全量 | 0.0445 | 0.0628 | 0.0231 | 0.1076 | 0.2021 | 0.1491 |
| 两路各 Top-10 | 0.3834 | 0.4214 | 0.2044 | 0.7667 | 0.9432 | 0.9025 |

结论限定在当前两路和这 44 条探索性报告：纯投票丢失了组内排序信息，效果低于 RRF，不推荐用它直接替代最终文件排序。可将两路一致出现作为候选共识标记。增加返回全量文件的语义路线，也只是给所有文件增加相同票数，不能解决区分能力问题；更多路线需定义有选择性的候选集，再单独验证。

### 实现与复现

实现位于 `src/bug_localization/voting.py`，不修改现有 BM25、AST 或 RRF。复用已保存的完整混合检索结果，离线运行，不查询 ES、不初始化模型，也不新增依赖：

```bash
python -B scripts/retrieval/vote_rankings.py --input-run results/hybrid/20261025_192040_178869 --depths all 10
# 只比较 AST96：追加 --semantic-label ast96
```

`--depths` 默认为 `all 10`，本轮没有搜索其他深度。正整数深度会自动保存相同候选集、常数 60 的 RRF 对照，明确区分候选截断与计票规则的影响。

本次输出：`results/voting/20261025_193450_036315/`。

- `summary.json/csv`：实际展示排序指标、同票随机排序期望、同候选池 RRF 对照；CSV 的 `ordering` 列区分这三种口径。
- `rankings.csv`：7,970 行纯投票排名，包含票数、投票来源和并列名次范围；同候选池 RRF 控制排名单独保存在其 `cases/` JSON 中。
- `cases/*.json`：每条报告的纯投票或 RRF 控制排名及真实标签。
- 各路线目录中的 `samples.json`：逐报告实际指标；投票路线另有 `expected_samples.json` 保存期望指标。
- `effective_config.json`、`verification.json`、`analysis.json`：输入/实现哈希、并列诊断和核对结果。

176 份计票排名、88 份同池 RRF 控制排名已独立复算，汇总及 CSV 与 JSON 一致；65 项测试通过，包括输入名次/分数无关性、每路去重和同票期望的全排列验证。这些数字描述当前实验，不是独立验证集或跨项目结论。
