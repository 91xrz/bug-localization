# C3 补充实验

2026-11-12 冻结补充方案。已有 500 条报告作为开发集；新的验证不复用这 500 条。

## 1. 候选召回 × 代码块选择

| 候选文件 | 原文 Top-3 选块 | 混合选块 |
|---|---|---|
| 原文 Top-50 | A（已有结果） | A3（新增运行） |
| 推测 Top-40，原文去重补足 50 | C1（已有结果） | C3（已有结果） |

混合选块先保留原文 Top-1，然后按推测相似度去重补足到最多 3 块。重排查询、模型、Max 聚合和平局规则全部固定。C2 保留为辅助对照。

新增 A3 保留同一 500 条清单，失败计零；第 308 条推测失败也计零。A 无推测依赖，因此该条仍按原文结果计分。主表反映完整运行策略的效果，不能把该失败造成的差别解释成纯选块质量。

除成对差异外，统计以下 2×2 对比：

- 召回主效应：`[(C1 − A) + (C3 − A3)] / 2`。
- 选块主效应：`[(A3 − A) + (C3 − C1)] / 2`。
- 交互效应：`C3 − C1 − A3 + A`。

结果：`results/c3_supplement/20261112_factorial500/`。完成后自动独立重建候选、选块、代码文本、文件 Max 排名及指标，并生成 `statistics/report.md`。

历史冻结检查发现 BM25 分析器溢出处理在实验之后更新。新流程从 Git 恢复与历史哈希完全相同的文件，比较 AST，确认只有 `analyze_query` 与 BM25 的 `run` 变化；指标和语义输入准备函数未变。兼容性依据单独记入新协议，不修改历史冻结文件。其他历史文件的哈希变化仍直接拒绝。

## 2. 配对统计、项目贡献与集中度

逐报告匹配数据行、项目、issue、提交、报告哈希和标签哈希。主指标 MAP@10，辅助指标 MRR@10、Top-1/5/10、MeanRecall@10。项目内配对 bootstrap 20,000 次得到 95% 区间；双侧配对符号随机化 20,000 次；Holm 校正覆盖同一次分析的全部对比和指标。置信区间本身未做多重校正。旧数据上的分析是探索性分析。

已完成的历史 500 条分析：

| 对比 | ΔMAP@10 | 95% CI | Holm p | 胜/平/负 |
|---|---:|---|---:|---|
| C3 − A | 0.012096 | [0.000220, 0.024298] | 0.7717 | 77 / 382 / 41 |
| C3 − C1 | 0.009304 | [-0.002125, 0.020920] | 1.0000 | 71 / 390 / 39 |
| C3 − C2 | 0.011977 | [0.001115, 0.023733] | 0.6400 | 30 / 443 / 27 |

这张表的校正族为 3 个对比 × 6 个指标；2×2 完成后的表包含更多对比，必须使用重新计算的校正值。

C3 − A 的项目平均差异：

| 项目 | ΔMAP@10 |
|---|---:|
| astropy | 0.003632 |
| django | -0.000808 |
| matplotlib | 0.022821 |
| xarray | -0.027815 |
| pylint | 0.031708 |
| pytest | 0.044289 |
| scikit-learn | 0.010404 |
| sphinx | 0.024476 |
| sympy | 0.000724 |

去掉任一个项目，平均差异仍为正（0.008118–0.017130），因此并非只靠某一个项目。但最大的 10 条正收益报告贡献了全部正收益的约 39.3%；去掉这 10 条后，剩余报告平均差异仅 0.000337。这是事后敏感性分析，不是重新筛选主评测集。现阶段不宜宣称稳定显著改善。

结果：`results/c3_supplement/20261112_existing_statistics/paired_statistics.json`，包含项目贡献、逐项目剔除、宏平均、最大变化报告和集中度。

## 3. LCA Python 外部验证

历史扫描发现 SWE-bench 全部 2,294 条报告都已有语义检索评测记录，无法据此构造从未评测过的测试集。按用户选择改用本地 LCA Python 测试集。

对 LCA 50 条报告检查历史清单、规范化正文（空白折叠、大小写归一）、项目和原始 issue 编号、修复前提交，以及已有推测缓存。3 条已有历史使用记录，预先排除：textualize/rich #2197、stevenblack/hosts #107、netbox-community/netbox #9895。冻结剩余 **47 条**，不按结果替换或剔除。LCA 的 `issue_id` 是数据行 ID；交叉核对使用 `issue_url` 中的真实编号。

清单：`configs/experiments/selections/c3_lca_py_holdout_seed20261112.json`，附历史清单哈希及排除理由。仅比较冻结 A 与 C3，不在 LCA 上继续挑选策略。沿用原实验 body-only 查询、Python 文件过滤、编码器、AST64、生成提示、生成预算和重排设置；通过 LCA 离线源码提供器读取作者指定的 PR base SHA。因保持原实验设置，本次查询不额外加入 LCA 标题。

主结果保留全部 47 条，失败计零；单独报告失败原因。A 不依赖推测成功。该规模只提供有限的外部证据，不能据此宣称覆盖所有项目。

外部泛化的区间使用按项目整体重采样和按报告配对重采样；LCA 多数项目仅一条报告，项目内分层重采样不能反映新项目的不确定性，不用于外部泛化判断。补算文件为 `results/c3_supplement/20261112_robust_intervals.json`，另附历史 499 条共同成功子集敏感性分析。

结果：`results/c3_supplement/20261112_lca_py_holdout/`。目录中 `new320` 是复用既有检索流水线的内部路径名称，实际样本数由冻结清单决定，为 47，绝不是新增 320 条。

## 4. 端到端耗时与成本

两种计时产物分开报告：

1. 外部验证全量记录各阶段时间、生成输入/输出 tokens 和重排 tokens。`costs.json` 是在线阶段时间之和，不冒充单次请求的实测墙钟时间；源码、切块、代码向量、索引准备和模型加载单列。查询嵌入是否命中缓存有明确记录。
2. 独立端到端基准在外部验证完成后运行，提前按固定种子从 47 条中选 9 条，每条重复 3 次，A/C3 交替顺序。三个模型常驻同一 GPU；共享代码向量和索引预先准备。每次重新生成功能推测，并绕过查询向量缓存。从收到内存中的报告开始，直到输出最终文件排名，以 CUDA 同步后的连续墙钟时间计时。准备时间和加载/预热时间另存，失败尝试保留。输出均值、P50、P95、峰值显存、tokens、包含失败的设备占用小时。重复测时不作为新的准确率样本。

端到端基准：`results/c3_supplement/20261112_end_to_end/`。它是当前完整研究流水线的耗时（包括检索一致性检查），不是经过服务优化的生产系统延迟。9 条 × 3 次的尾延迟估计仍较粗。

模型均本地运行，没有 API 计费。未提供设备小时单价，因此金额保留为空；设备占用时间不能直接冒充电费或实际 GPU 运算利用时间。价格给定后可用设备小时 × 单价换算；电费还需要能耗测量。

## 运行与恢复

- 主入口：`scripts/experiments/run_c3_supplement.py`，`--mode factorial` 或 `--mode holdout`。
- 统计入口：`scripts/analysis/analyze_c3_supplement.py`。
- 连续请求计时：`scripts/experiments/benchmark_c3_end_to_end.py`。
- tmux：`irbl-c3-factorial-500`（GPU 0）、`irbl-c3-lca-holdout`（GPU 1）、`irbl-c3-latency`（等待外部验证完成，再使用 GPU 1）。
- 各输出目录的 `status.json` 表示实际进度；未完成时不把中间结果当作最终结论。

使用同一输出目录恢复主流水线，协议、实现和输入哈希必须一致。每条结果保存断点与哈希；完整性审计后才生成最终统计。新出现的异常会阻止审核完成并记录原因。

## 汇总恢复

本次两组评分已完整保存，初始汇总因新记录未含 `missing_gold` 字段而中断。使用 `scripts/experiments/finalize_c3_supplement.py` 从保存的标签和候选清单重建覆盖字段，并执行独立审计。原始 `samples.json` 与各条评分文件不变；修复副本写入 `samples_with_coverage.json`。恢复脚本和原始记录哈希保存在 `postprocessing_recovery.json`。该恢复不重跑模型，不修改已冻结方案。

```bash
.venv/bin/python scripts/experiments/finalize_c3_supplement.py --mode factorial --output results/c3_supplement/20261112_factorial500
.venv/bin/python scripts/experiments/finalize_c3_supplement.py --mode holdout --output results/c3_supplement/20261112_lca_py_holdout
```

统计补算由 `scripts/analysis/analyze_c3_uncertainty.py` 完成；最终汇总文档由 `scripts/analysis/report_c3_supplement.py` 在三个运行全部完成后生成。
