# 历史探索：AST64 局部上下文与作用域切块实验

本实验保留以便复现与审计；AST64 是基线，以下增强路线不作为已验证创新点。

## 预先固定的比较

使用原 `blagent_ast`（1500 字符，512 总 tokens，64 前缀 tokens）作为基线，按原 44 条 Requests 清单比较五个独立候选。所有路线使用同一修复前快照、候选文件、原始报告、Qwen3-Embedding-0.6B、Max 文件聚合、@10 指标，不做 RRF。MAP@10 为主要指标，MRR@10 和 Top-1/5/10 为次要指标；结果属于已多次观察过的同项目探索，不是独立测试。

| 路线 | 固定规则 |
| --- | --- |
| `ast_control` | 对从函数中间开始的块，追加当前块起点所在控制结构的真实头部，例如 if 条件；仅 Python。 |
| `ast_variables` | 对同样的块，识别正文里的标识符，追加当前函数中该名称最近的简单赋值；仅 Python。静态文本匹配不等于数据流分析，条件分支赋值也不保证运行时到达。 |
| `ast_local_both` | 按上述顺序先尝试控制头，再尝试简单赋值。 |
| `ast_scope` | 在原块内存在多个函数起点时，沿函数起点分割；如果第一个函数已在块前开始，也在后续函数起点分割。仅改变必要边界，不合并块。 |
| `ast_overlap` | 给函数中间开始的块，追加同一函数中最近结束的一个语句；仅 Python。重叠内容仅进入编码文本，原始正文仍无重叠。 |

前三条和重叠路线保留原块边界、正文与前缀；附加文本整体最多 64 tokens，总输入不超过 512，只追加能完整放入的片段，不为其截短正文。附加内容和字节位置来自相同文件的修复前源码，不读取报告或缺陷标签。作用域路线重新计算切开后的真实前缀；若超预算则对整个文件退回原边界。所有路线完整重建原源码。非 Python 的局部上下文路线保留原块，不支持多语言依赖推断。语法恢复可能影响上下文质量。

这些规则不是完整的程序切片：局部定义采用简单词法匹配，可能包括函数内不可达或条件性赋值；控制头只涵盖起点所在节点的主体，不推断 else 分支。有限预算和低触发率可能导致检索结果不变。重叠策略也可能因语句被预算跳过。函数起点切分不保证每个块只含单个函数，嵌套函数亦可能切开。

## 复现

```bash
python -B -m unittest discover -s tests -q
python -B -u scripts/retrieval/run_vector_batch.py --config configs/experiments/ast_local_experiment.json --selection <44条selection.json>
python -B scripts/analysis/analyze_ast_local_experiment.py <运行目录>
```

首次调用前启动本项目 Elasticsearch。分析脚本检查每条报告的配对、候选/标签、指标、源码字节顺序、上下文来源、输入预算、ES/NumPy 分数和聚合排序；输出 20,000 次以报告为单位的配对 bootstrap 区间（seed 20261028）及块和上下文覆盖。由于报告共享项目和源码，区间仅描述这组样本。缓存预热状态、路线执行顺序均影响耗时和新增向量数量，它们不能作为公平的冷启动成本。

其他路线相对 AST64 的 AP 胜/平/负分别为：局部定义 3/39/2、组合 3/39/2、作用域边界 7/24/13、相邻语句 2/40/2。作用域边界产生约 26.7% 更多块，但 MAP 下降 0.04958；若干报告有大幅改善，也有较多退化。局部定义与组合路线指标完全相同，不等于两条路线编码文本完全相同。

本机当前基线 MAP 为 0.6289，和旧记录 0.6297 略有差异；本次判断使用同一次运行的配对基线，不混合两次运行的数值。本批是已观察过的单项目样本，控制条件候选只由一条报告驱动，不能认定已获得稳定提升。所有候选均保留为实验路线，不替换默认 AST64。

在 Requests 完成后，按既有清单追加 `blagent_ast` 和 `ast_control` 两路：Seaborn 22 条、Flask 11 条、pytest 11 条。此清单的原始检索结果此前曾在模块2实验中观察，因此是跨项目复核，并非完全未接触的最终测试集。两路各 44/44 成功，结果位于 `results/vector/batches/swe_bench_formatted_test_20261028_233018_317319`。
