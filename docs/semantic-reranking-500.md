# 500 条报告扩展实验

本轮沿用[180 条修正版](semantic-reranking.md)的模块分工：**功能推测只用于第一阶段语义检索，重排只读取原始缺陷报告和候选代码块**。固定 Qwen3-8B 直接功能推测、Qwen3-Embedding-0.6B AST64 召回、Qwen3-Reranker-0.6B、Top-50 文件、每文件语义 Top-3 块、Max 文件聚合及 @10 指标，不搜索参数。

## 样本与对照

## 自动流程

入口 `scripts/experiments/run_reranker500.py`，配置 `configs/experiments/hypothesis_reranker500.json`。

1. 为新增 320 条生成功能推测，复用相同身份的缓存。
2. 同一修复前快照、候选、代码块和向量分别检索原报告与功能推测。使用与 180 条相同的编码器身份和精确 ES 评分，并保留原有 NumPy 核对。
3. 两组候选分别使用**完全相同的原报告输入**做重排。沿用原报告编码阶段的文本截断，不向重排输入添加推测文本。
4. 独立复算两组重排，校验来源哈希、样本、候选、排名及指标。
5. 合并既有 180 条，输出新增320／合计500／原有180三组的整体及分项目结果、配对 AP 胜平负。

阶段在独立进程中运行，生成功能推测后释放其显存。本轮最初在 GPU 0 串行执行，后按用户要求切换到 GPU 0＋GPU 1 并行：GPU 0 续跑剩余检索，GPU 1 先重排已提交的检索样本；检索完成后，两卡共同处理剩余重排。GPU 1 上的既有服务保留，重排模型使用其空余显存。源码快照已全部在本地。为避免 320 个新索引占满 ES 分片上限，只清理由本轮当前样本新建且所有权指纹核验通过的临时索引；预先存在的索引不删除。完整块分数、查询和排名保留在结果中，代码向量缓存继续保留。

```bash
.venv/bin/python scripts/experiments/prepare_reranker500.py
.venv/bin/python scripts/experiments/run_reranker500.py --output results/hypothesis_reranking/YOUR_RUN --check-only
.venv/bin/python -u scripts/experiments/run_reranker500.py --output results/hypothesis_reranking/YOUR_RUN
```

使用同一输出目录可恢复未完成阶段，要求配置、输入和实现指纹不变。检索阶段按样本保存检查点；重排沿用逐样本续跑。失败样本不替换、不从分母移除，功能推测失败不会自动回退为原报告；失败的路线按 0 计分，最终状态明确标记 `completed_with_failures`。进程或基础设施异常标记 `failed`，保留诊断供修复后续跑。

## 输出

- `automation_status.json`：阶段、进程与失败原因。
- `generation_progress.json`、`retrieval_progress.json`：新增样本处理进度。
- `generate.log`、`retrieve.log`、`rerank_original.log`、`rerank_hypothesis.log`：各阶段日志。
- `new320/semantic/`、`new320/hypothesis/`：原报告和功能推测召回证据。
- `new320/original_reranking/`、`new320/reranking/`：两条重排路线和独立审计。
- `final_summary.json`、`comparison.csv`：四种方案分别在新增320、合计500及原有180上的指标。
- `project_summary.json`、`paired_samples.json`：分项目指标和逐报告配对记录。

尚未完成前不将部分处理样本视为 500 条最终结果。

本轮已在 tmux 会话 `irbl-hypothesis-reranker-500` 启动，目录为 `results/hypothesis_reranking/20261111_153819_040009_500/`。总入口日志在同级 `20261111_153819_040009_500.log`；阶段状态、进度和详细日志在运行目录内。聊天不持续轮询、不逐条播报结果。

多卡接续入口为 `scripts/experiments/parallelize_reranker500.py --run <运行目录>`，同一 tmux 会话继续托管。切换时保留已完成的 294 条检索和 81 条前缀重排；冻结前 292 条为可立即处理的分区，剩余 28 条在检索结束后建立另一分区。`parallel_status.json` 记录物理 GPU、工作进程与分区进度，`parallel_execution.json` 保存接续程序指纹和执行策略。每个进程通过 `CUDA_VISIBLE_DEVICES` 选择物理卡，在进程内仍使用 `cuda:0`；两卡型号相同，模型身份会再次核对。

每个分区保留相同的原报告输入、候选代码、批次大小和评分规则，按原样本位置合并并拒绝重复或缺失记录，再由原审计与汇总代码复算。既有科学参数和原始实现指纹不修改，多卡只改变执行调度；已记录的输入长度超限报告仍按原失败口径计分。数据准备、磁盘读取和 ES 评分期间 GPU 利用率可能较低，不保证两卡始终满载。

## 最终结果

2026-11-11 21:45（北京时间）完成全部阶段，状态为 `completed_with_failures`。原报告两条路线均 500/500 成功；功能推测两条路线均 499/500 成功，唯一失败为新增样本 Xarray #5662 的生成输入超过上限。该报告保留在 500／320 分母中，功能推测相关路线按 0 计分，不过滤或替换。

### 新增 320 条

| 方案 | MAP@10 | MRR@10 | Top-1 | Top-5 | Top-10 | MeanRecall@10 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 原报告 | 0.515945 | 0.562901 | 38.44% | 80.31% | 87.50% | 0.801334 |
| 原报告＋重排 | **0.644022** | 0.703172 | **57.81%** | **87.19%** | 90.00% | 0.841044 |
| 功能推测召回 | 0.552521 | 0.615740 | 45.31% | 85.00% | 90.31% | 0.820188 |

组合相对原报告＋重排：MAP 降低 0.002634，MRR 近乎持平（+0.000136），Top-1 少 1 条（185 → 184），Top-5 少 2 条（279 → 277），Top-10 多 6 条（288 → 294）。逐报告 AP 为 57 胜、223 平、40 负；胜的样本更多但 MAP 略低，说明部分退化样本的下降幅度较大。

新增 320 条中，Matplotlib、Pylint、pytest、scikit-learn、Sphinx、SymPy 的 MAP 提高，Astropy、Django、Xarray 下降。原报告＋重排相对原报告的 MAP 提高约 0.1281；重排的主要收益在新增样本上仍然存在。

失败样本在原报告＋重排下的 AP 为 1/3。即使额外只看双方均成功的同一 319 条，组合相对原报告＋重排的 MAP 仍略低（约 -0.0016）；主结果继续使用完整 320 条分母，不以成功子集替代。

### 验证与结论

原报告重排的新增 320 条已独立复算。组合路线的 319 条成功样本也完成来源哈希、原报告 Query、候选池、块分数聚合、文件排名及指标复算；另核对完整 320 条主指标确实将失败计 0。补充审计为 `new320/reranking/verification_with_failures.json`，诊断性成功子集保存在 `successful_subset_audit_blagent_ast/`，不改变主分母。该审计由 `scripts/analysis/audit_reranking_failures.py` 执行，已纳入 `final_summary.json` 的 audits 字段。

**扩样后的判断：重排本身仍有较大收益；功能推测作为第一阶段增强，提高了前十覆盖，但未在新增 320 条上复现额外的 MAP 提升。** 因此应将其描述为覆盖与头部排序之间的取舍，不能据合计 500 条的小幅正增益认定功能推测具有稳定的额外排序收益。本轮没有针对新增样本调参，也未做显著性检验。
