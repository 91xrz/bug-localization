# C/D 混合召回实验（500 条）

本实验比较哪一路适合作为主召回。沿用已完成实验的同一批 500 条报告，另行汇总原 180 条和新增 320 条。冻结清单为 `configs/experiments/selections/crossproject_500_seed20261111.json`。

| 方法 | 候选文件 | 重排查询 | 每文件代码块 |
| --- | --- | --- | --- |
| A（历史对照） | 原文 Top-50 | 原始报告 | 原文语义 Top-3 |
| B（历史对照） | 功能推测 Top-50 | 原始报告 | 功能推测语义 Top-3 |
| C | 功能推测 Top-40，按原文排名补足 50 | 原始报告 | 原文语义 Top-3 |
| D | 原文 Top-40，按功能推测排名补足 50 | 原始报告 | 原文语义 Top-3 |

先固定主路的前 40 个文件，再顺次扫描另一路完整排名，跳过已选文件，补足 50 个不同文件。若整个文件集合不足 50 个则全部保留。没有分数加权或 RRF；候选选择不读取修复标签。

C/D 统一按原文语义分数选择每个候选文件的最多 3 个代码块，使共同文件的代码块及文本一致；这是本次采用的默认口径。重排查询复用原文编码器实际使用的报告文本，保留原有 512-token 截断，去掉语义编码器的指令包装。功能推测只参与候选文件选择，不进入重排查询或重排文档。

重排器仍为本地 Qwen3-Reranker-0.6B，batch=16、max_tokens=1536、BF16；代码块得分为 yes/no logit 差，文件得分为其代码块得分最大值。C/D 的候选按原文排名排列后送入重排器，文件得分相同也按原文排名打破平局。模型文件、运行环境、参数与历史对照核验一致。

**比较限制：** B 历史对照使用功能推测选代码块；C/D 使用原文选代码块，因此 C/D 与 B 的差值同时包含代码块选择差异。判断主召回方向以 C 与 D 的直接比较为准。A 与 C/D 的代码块选择口径相同。不同批次组合的 BF16 运算也可能产生小幅数值差异。

两组都依赖两路检索成功。全局位置 308（新增部分第 128 条，pydata/xarray #5662）的功能推测已因输入超长失败，两组均记录依赖失败并以零分计入全部 500 / 新增 320 的分母；不替换样本，也不退回单路检索。其他运行错误会单独记录。成功子集指标仅作诊断。

## 后台执行与产物

- 配置：`configs/experiments/mixed_recall_reranker500.json`
- 运行入口：`scripts/experiments/run_mixed_recall500.py`
- tmux：`irbl-mixed-recall-CD-500`
- GPU 0 执行 C；GPU 1 执行 D；每组独立断点保存。
- 输出：`results/mixed_recall_reranking/20261111_CD_500`

读取 `status.json` 查看整体阶段；`C/progress.json`、`D/progress.json` 记录进度。完成后自动复核源文件哈希、原文查询、去重补足规则、原文 Top-3 代码块、Max 聚合、平局顺序和评估指标。`final_summary.json` 与 `comparison.csv` 包含 A/B/C/D 的 MAP@10、MRR@10、Top-1/5/10、MeanRecall@10，以及 C/D 候选池召回率、命中率、补充召回挽回的报告比例和逐报告 AP 胜平负；`project_summary.json` 为项目分组结果。

每条结果保存候选文件来源、两路原排名、实际重排查询、代码块文本与分数、最终排名、修复标签及源文件哈希。结束后审计会将已知依赖失败与新增异常分开列出。

可用相同入口、相同输出目录恢复中断；已冻结源文件、配置或实现发生变化时会拒绝恢复。避免同时向同一输出目录启动多个控制器。

```bash
.venv/bin/python scripts/experiments/run_mixed_recall500.py \
  --output results/mixed_recall_reranking/20261111_CD_500
```
