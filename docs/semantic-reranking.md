# Qwen3 语义检索后重排

本页记录基础逐块 Max 重排接入。当前完整 C 包含逐块评分、文件联合评分和初排分数，见 [A+B+C 方法](main-method.md)。

后续规模扩展见 [500 条报告扩展实验](semantic-reranking-500.md)：复用原有 180 条，新增 320 条单独验证，维持功能推测仅用于第一阶段的正确分工。

第一版在已有语义文件排名后增加本地 `Qwen3-Reranker-0.6B`，不训练模型。默认比较 AST64 的原始排名和重排结果；同一入口也支持 dynamic、method、fixed 路线。重排直接读取语义批次保存的代码块及分数，无需重新编码或启动 Elasticsearch。

## 固定协议

- 按原语义文件排名取前 50 个文件；不足 50 时全部使用。
- 每个文件按原始余弦分数选择最高的 3 个块；不足 3 块时全部使用。语义块同分按 chunk_id 排序。
- Query 严格复用语义编码器实际看到的报告正文（包含其原有截断），去掉 embedding 专用指令包装；Document 使用原来的结构前缀和代码 `embedding_text`。不添加增强报告、修复后代码或标签。
- 使用模型本地 README 的官方 yes/no 提示格式，任务指令与语义检索一致。左填充，在最后一位计算 `logit(yes) - logit(no)`，同时保存 sigmoid 概率。用 logit 差排序以避免概率饱和产生不必要同分。
- 文件分数取选中块重排分数的最大值；同分保留原语义名次。未进入前 50 的文件按原顺序接在末尾，分数记为 null，不与重排分数混用。
- 默认单卡 BF16、batch size 16、总预算 1536 tokens。超过预算明确报错，不静默截断；仅最后一位计算词表 logits，无生成过程。CPU 显式选择后使用 FP32。
- 使用相同的样本、快照、候选和标签，计算 MAP@10、MRR@10、Top-1/5/10、MeanRecall@10。缺失标签保留在分母，失败计 0，并记录失败数；不把失败当作成功后回退原排名。

配置见 `configs/retrieval/reranker.json`。首轮采用既有 Requests 44 条 AST64 批次，参数在观察正式结果前固定。

## 运行

在项目根目录运行：

```bash
.venv/bin/python scripts/retrieval/run_reranker.py \
  --semantic-run results/vector/batches/swe_bench_formatted_test_20261028_182913_608877
```

`--limit 1` 可做冒烟检查；`--routes dynamic method fixed blagent_ast` 可比较全部四路；`--device cuda:0`、`--batch-size 16`、`--top-n-files 50`、`--chunks-per-file 3` 可以覆盖配置。设备编号相对于现有 `CUDA_VISIBLE_DEVICES`，脚本不修改设备可见性。

新检索可直接追加 `--rerank`，在选定的语义路线完成后自动运行配对重排：

```bash
.venv/bin/python scripts/retrieval/run_vector_batch.py --routes blagent_ast --limit 44 --rerank
```

用 `--reranker-config` 指定重排配置。也可先生成语义批次，再将其目录传给独立入口的 `--semantic-run`。不会修改输入批次或原检索配置。

输出为独立的 `results/reranking/<run_id>/`：

| 文件 | 内容 |
| --- | --- |
| `summary.json/csv` | 原排名、重排指标、差值、成功/失败数、AP 胜平负及耗时 |
| `samples.json` | 各路线逐样本的配对指标与失败诊断 |
| `selection.json` | 本次样本顺序、原始 selection 指纹及本次选择指纹 |
| `effective_config.json` | 模型文件哈希、推理环境、参数、输入协议及原实验配置 |
| `cases/*/*_result.json` | 完整重排、原名次、实际查询、所选代码块及分数、输入文件哈希 |

候选清单、块分数校验和及样本身份在处理时核对。结果文件足以独立重算文件排序和评测指标。每完成一条写入汇总；中断时状态保持 running。用 `--resume <原结果目录>` 可保留已完成的配对样本继续运行，要求样本、来源、参数及模型环境一致；续跑实现指纹记录在 `resume_history.json`。多路线仅支持所有路线完成数量相同的检查点。

## 适用范围

这是“语义 Top-50 文件 → 每文件 Top-3 块 → 相关性重排”的固定方案，不是对全文件内容或全部代码块评分。未进入候选池的相关文件不能靠重排提升到前 10；相关性高也不保证文件就是修复位置。单项目 44 条结果不能直接推广到全量 SWE 或跨项目场景。

## 修正流程：功能推测召回，原报告重排

功能推测仅用于第一阶段生成检索查询并进行 AST64 语义检索。第二阶段 Qwen3-Reranker-0.6B 的 Query **只包含原始缺陷报告**，Document 仍是候选代码块的结构前缀和正文，不拼接功能推测。

固定流程：原报告 → 功能推测 → 语义排名前 50 个文件、每文件语义 Top-3 代码块 → **原报告与候选代码相关性评分** → Max 文件聚合。第一阶段文件及代码块的选择与历史变体完全相同，只更换重排 Query；原报告使用与“原报告＋重排”对照完全相同的实际文本及既有 512-token 编码截断，避免同时改变上下文范围。1536-token 重排总预算、模型、任务指令、批次及聚合规则均不变。

实现将候选来源 `source_query_route=direct_hypothesis` 与重排输入来源 `reranker_query_source=original_report` 分开记录。逐样本保存原报告输入来源与哈希；审计独立核对实际 Query，并在四种对照汇总前逐条与原报告重排输入比较。旧变体不能用新实现继续追加结果。
