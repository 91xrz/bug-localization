# C 重排器 LoRA：区分报告相关文件与修复文件

## 事前设计

本轮只修改 C 的打分权重，A/B 检索、候选、代码块、文件 Max 聚合和同分顺序均不作为可调参数。主问题是：把同一报告的已修复文件和容易混淆的未修改文件作对比训练，能否在其他项目上提高端到端 MAP@10？“未修改”依据补丁文件标签，是弱负例，不是人工标注的“症状原因”。

- **训练/验证**：从本地 BeetleBox train 中选 160/32 份报告；验证整项目与训练隔离。只读取报告正文和修复前源码。修复路径标签只用于构造样本或计分，不把 PR 标题、补丁文本、修复后代码送给模型。为了可训练，训练池须同时存在正例与负例；这个筛选不应用于最终 SWE 评价。
- **模型**：同一 Qwen3-Reranker-0.6B 和既有修复相关指令。在注意力的 Q/V 投影加入低秩适配器，保持其他参数冻结。按报告聚合代码块得到文件最高分，在同报告的正负文件间学习相对顺序，不将正文件里的所有块都标成故障代码。以固定两轮后的适配器做一次主比较，不用 SWE 选择超参数。
- **测试**：从既有 SWE 开发 500 的九个项目各按身份选十条，承认这不是未观察过的新基准。测试项目与 BeetleBox 训练和验证隔离。复用原 C3 的真实候选、查询与块，基座和适配器重新打分，缺失标签或上游失败仍保留在主指标分母中。不抽取“BLAgent 赢”或“C3 输”的报告。
- **主指标**：每报告 AP@10 的均值及 LoRA 减基座的配对差，附项目内分层的置信区间。Top-1、MRR、Top-10、分项目及同批 BLAgent 本地适配版仅作辅助比较。单一训练种子，一个验证项目；不根据测试结果挑轮次、换种子或叠加提示改动。
- **机制诊断**：在测试标签已与模型输入隔离后，每报告取固定候选池中的修复文件，对比重排前顺序最靠前的五个未修改文件。计算正文件得分更高的比例（平局按半次），每报告再取平均。另单列“路径形似测试的未修改文件”；真实修复的测试文件始终算正例。没有可比正负对的报告不进入机制分母，仍进入端到端评价。指标是与修复标签的一致率，不能证明模型学到了故障因果。
- **保留规则**：只有在相同输入上比基座提升且配对区间支持正收益，才认为有证据替换原 C。若仅训练/验证集上涨但 SWE 下降，保留负结果，不在这 90 条上继续调参。项目外迁移不等于时间盲测。

在得到主测试的 LoRA 预测之前，增加一个只作诊断的外部对照：不再训练，使用同一适配器、既有 LCA Python 47 条全清单及原 C3 输入。两套评测单独报告，不择优、不合并。理由是 BeetleBox 训练池内有 49/260 个修复文件的路径形似测试文件，而本次 SWE 的 154 个标注路径均不符合该规则；不能把“降低测试文件的排名”本身当成学会了故障定位。

## 数据与复现

160 条训练分别来自 Airflow 51、PostHog 54、Odoo 55；32 条验证全部来自 LocalStack。训练共 900 个文件（260 个修复、640 个未修改）、1,701 个报告/代码块对。为控制准备成本，训练负例从路径与报告词汇匹配的前 18 个未修改文件中，按代码窗口与路径相关度选 4 个；最多取 3 个存在于修复前源码的正文件。正负文件均以同一规则各选最多 2 段。**训练使用词法挖掘和代码窗口，不是原 B 的候选分布**。验证也注入正例，不把其分数当作端到端 MAP。SWE 实际测试不注入正例：基座和 LoRA 使用同一原始 C3 查询、每报告实际至多 50 个候选文件、每文件最多 3 个块，1536 tokens 上限。

## 实测结果（2026-11-20）

**决定：不替换 C3。** 训练/验证的区分能力有提高，SWE 主测试上的端到端 MAP 却低于未微调模型，LCA 的正向差值也未排除零。两个测试集不合并、不用来挑选模型。

| 阶段 | 原 C3 / 未微调 MAP@10 | LoRA MAP@10 | 差值 | 配对 95% 区间 | Top-1 原 → 新 |
|---|---:|---:|---:|---:|---:|
| LocalStack 验证 32（注入正例的抽样池） | 0.470366 | 0.497950 | +0.027584 | 不作主推断 | 未作主比较 |
| SWE 主测试 90（9 项目） | 0.682872 | 0.662475 | −0.020398 | [−0.057049, +0.017218] | 58 → 55 |
| LCA 外部诊断 47（45 项目） | 0.574786 | 0.609943 | +0.035157 | [−0.003448, +0.078864] | 32 → 32 |

SWE 的 90 条从既有开发 500 中选择，另排除了之前的开发 45、确认 90；1 条上游失败在两组都计零，89 条实际打分合计 12,328 个报告/块输入。基座逐报告指标全部复现。按 AP，LoRA 为 14 胜、56 平、20 负；有 6 条纠正了首位，另有 9 条丢失原先正确的首位。MRR@10 从 0.756896 降至 0.737077，Top-10 均为 84/90。SWE 按项目内的报告配对重采样。相同清单上的本地 BLAgent 8B 的 MAP@10 为 0.662071、Top-1 为 62/90；不据 LoRA 的 0.000403 点估计差宣称超越，更不能与 BLAgent 论文原设定混比。

LCA 两组均 47/47 成功，按项目整体重采样。AP 为 15 胜、22 平、10 负；Top-10 均为 45/47，MeanRecall@10 从 0.746454 升至 0.769504。未从该结果挑选训练轮次。

**机制诊断。** LocalStack 验证在抽样候选中的正负对胜率从 64.78% 升至 70.51%。SWE 的 86 条可比较报告共有 635 个“修复文件—原始候选顺序靠前的未改文件”对，每报告平均胜率仅从 86.23% 升至 86.57%；只看路径似测试的未改文件为 95.48% → 96.20%。LCA 同一预设主负例规则有 46 条、543 对，胜率 73.51% → 75.36%。训练和验证用抽样池，测试用真实 C3 候选，这些绝对值不应跨池直接相减。弱负例不是人工判定的症状或根因。较多正负对排对并不意味着排第一的文件也对。

训练参数为 rank=8、alpha=16、学习率 5e-5；每 4 份报告更新一次，固定两轮共 80 步，更新 1,146,880 个参数。含验证耗时 446 秒，不含数据准备和端到端检索。使用已有评分模板、yes/no logit 差和 file-Max；训练时报告和代码各自限 512 tokens，测试时完全复用历史 C3 已选输入。独立审计检查输入及打分校验和、各文件最高块得分、同分排序、逐例 AP 和困难对胜率。

**下一轮建议**：不在 SWE90 或 LCA47 上挑参数。先对另一批训练报告实际运行冻结 C3，以其排在修复文件之前的未修改文件（特别是前 1–5 名）作为训练竞争者；对照现有词法挖掘。在同一规模、同种子、同 LoRA 配置下，用真实 50 文件池的留出项目 MAP 和原本正确首位的保留率作开发决策。该假说尚未验证。
