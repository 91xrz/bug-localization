# 0.6B → 8B联合重排：扩到500条与机制分析

2026-11-21 已使用两张4090完成同一批固定500条，491成功、9失败，失败全部计零。复用原C3已审计的0.6B排名与代码块，重新执行全部500条8B阶段，不拼接历史小批的成功结果。双卡分担同一个BF16模型，两个32K并发槽位；保持此前选定的Top10提示词、温度0、关闭thinking、2048输出tokens和最多一次排列纠正。全部输入、请求、输出排列及指标的独立核验通过，本次模型服务已释放。

相对原C3，ΔMAP=+0.085729，95%项目内分层配对bootstrap区间[+0.059214,+0.112777]，AP胜/平/负157/271/72，12项Holm校正p=0.002400。原180条MAP从0.633333到0.730331，新增320条从0.653455到0.732845，方向一致。

相对直接8B，ΔMAP仅+0.011672，区间[−0.013352,+0.036307]，Holm校正p=1.0；Top1低1.6个百分点。Top5提高4.8个百分点（校正p=0.012597），Top10提高3.6个百分点（校正p=0.106379）。因此两阶段更适合保留较好的候选覆盖，不能声称所有指标都更优。

这里原C3的0.6B采用原文语义名次处理同分；前一轮报告中的0.6B采用RRF同分规则，MAP=0.645629、Top10=93.0%。完整结果同时列出两者，不混用基线。

## 8B具体改变了什么

1. **把已召回的正确文件提到前面。** 首位112条由错变对、38条由对变错，净增加74条（14.8个百分点）。38条回退中36条是有效输出排错、2条是输出失败。112条纠正中，正确文件原第2名68条、第3名12条、第4名14条、第5名8条，第6–10名10条。主效应是前十内部的排序，不是新召回。
2. **降低部分测试文件对首位的干扰。** 112条纠正中43条的原首位是测试路径。按路径启发式，56条从测试路径改为非测试路径，其中43条改后命中标签，仍有13条没有命中。不能把这一观察推广为“测试文件都不该修”，也不能仅凭路径断言模型理解了根因。
3. **收益不完全来自完整报告。** 原报告未扩展的296条，平均ΔMAP=+0.061102；扩展的203条为+0.122061。前者对500条总ΔMAP贡献+0.036172，后者+0.049557。这是分组相关性，不是报告长度的因果消融；较长报告也可能本来就更困难。
4. **保留0.6B的主要价值是候选选择，而非必然增强8B判断。** 两种8B流程499条完整报告全部一致，共同文件的代码块也全部一致。双方成功且前十内正确文件集合相同的403条上，两阶段平均ΔMAP反而为−0.018110；正确文件集合不同的76条上则为+0.164573。该分组依赖事后标签，不能当因果估计，但提示总体小幅收益主要伴随候选覆盖变化。

每个成功样本的前十集合和第11名后尾部都经核验保持不变。新增8B失败使7条原先Top10命中的报告计零，所以整体Top10从92.6%降至91.2%。

## 代码证据支持的案例与反例

以下为助手对实际报告、实际输入代码和输出解释的事后核查，不等同于补丁执行验证。模型自述与可核实代码分开判断。

| 案例 | 排名变化 | 可核实的观察 |
|---|---|---|

| Pylint #6820，[样本94](../results/c3_joint500/20261121/review/0094.md) | 10→1 | `config/utils.py`实际含`PREPROCESSABLE_OPTIONS`、`--load-plugins`和`_preprocess_options`，与CLI拼写差异的处理直接相关；报告没有扩展。0.6B首位为通用`pylinter.py`。 |

| Matplotlib #24637，样本57 | 2→1 | 原首位测试块展示gid和SVG症状；正确`offsetbox.py`包含`AnnotationBbox.draw(renderer)`。8B优先了具体绘制实现；这条报告有所扩展，不能把收益全部归为联合比较。 |
| Sphinx #8863，[样本156](../results/c3_joint500/20261121/review/0156.md) | 1→5 | 报告明确限定LaTeX；8B却因长行/换行概念选择`writers/text.py`。实际输入中`writers/latex.py`已含LaTeX代码块的`visit_literal_block`，属忽略后端限定的退化。 |

这组证据支持的较稳妥解释是：8B在一部分样本上更好地区分了“相关概念、调用入口、测试复现”与“实际控制行为的实现”，同时也会被相似概念吸引或误解场景。现有设置同时改变模型规模、联合输入、提示词和计算预算，尚未隔离每项贡献。

## 为什么没有重现旧90条的0.7809

这次同90条重新运行的MAP为0.767519、Top1为82.22%，旧值为0.780866、84.44%。89条成功样本中84条AP不变、2条提高、3条下降，另有1条本轮格式失败；本次未挑选旧成功记录替换。即使温度0，同一双卡后端也不应假定跨运行逐位一致；此次未隔离数值或调度变化的具体来源。

排除旧45条开发和90条确认后的365条，两阶段MAP=0.717674，原C3=0.646627、直接8B=0.711376。这支持相对0.6B的改善可以扩展，但不支持用旧90条的较高点估计代表全部500条。365条仍属于历史开发数据，不能称为新盲测。

新增8B阶段55.40分钟、626次调用、输入5,302,269和输出178,412 tokens。9条失败含6条排列不完整、2条输出预算耗尽、1条上游失败；不是端到端计时。8项相关输入隔离及审计测试通过，完整500条也已独立复算。

## 为什么要同时保留两阶段

0.6B阶段对50文件的代码块独立打相关性分数，文件分数取最大块分数。8B阶段把0.6B前十的多个文件及各文件最多3块同时交给模型，要求比较可能修复的位置、竞争实现、调用者和复现测试，再返回完整排名。8B阶段不访问修复标签、补丁，也不新增文件或源码块。

两者改变的内容不同：0.6B帮助从50文件中保留高覆盖的前十；8B利用同场比较重排前十。成功样本的前十集合不变，8B新增的贡献应从首位、MRR和AP的变化判断，不能解释为新增召回。

## 旧90条的可验证观察（不是本轮500条结果）

- 首位23条从错变对、3条从对变错；53条保持正确、11条仍然错误。
- 纠正的23条中，正确文件原先第2名16条、第3名1条、第4名5条、第5名1条。主要是已召回的近似候选之间重新判断优先级。
- 原报告没有扩展的53条，MAP平均增加0.112367（19胜、7负）；原报告扩展的37条，增加0.165416（15胜、3负）。这排除了“所有改善只是因为完整报告”的解释，但不是报告长度的因果消融。
- 旧45条开发控制中，仅把0.6B的报告恢复完整，MAP从0.641878到0.662910；8B联合重排为0.788307。模型大小、输入比较方式、提示词和计算预算一起变化，不能单独宣称全部改善由参数量或联合比较造成。

已有代码证据支持的例子：Django #14667中，`django/db/models/query.py`的`defer/only`主要调用底层方法，`django/db/models/sql/query.py`的`add_deferred_loading`实际维护`deferred_loading`集合。旧90条8B将后者从4升到1，报告与0.6B输入相同。Pylint #6526中，统计数据类`linterstats.py`与真正决定`.stats`文件路径的`caching.py`不同；后者从5升到1，报告同样没有扩展。这支持“区分相关概念与负责行为的实现”的解释。

模型自述不能直接视为真实修复机制。例如Django这一条虽排对文件，解释中曾混淆`defer/only`的先后顺序。因此需要把排名事实、代码中可核实的行为、模型推测分开。

## 本轮分析协议

同500条对比原C3、直接8B、两阶段8B；另外列出RRF同分规则下的0.6B和本地BLAgent。主配对统计仅对两阶段相对原C3及直接8B做12项指标Holm校正；原180、新320及排除旧45+90后365条分别汇总。所有数据均属历史开发样本，365条也不是新的盲测。

分析首位纠正/破坏、正确文件原名次、报告是否扩展、测试路径是否让位给实现、与直接8B的前十标签覆盖差异。按最大AP改善8例、最大下降8例和身份哈希选出的未变4例形成证据包，既看成功也看失败；该抽样不能用于估计机制发生频率。
