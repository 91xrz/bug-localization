# IGSIL / CoSIL 文件级实验

更新：2026-11-16。接入 ASE 2025 *Issue Localization via LLM-Driven Iterative Code Graph Searching* 的作者文件级流程。会议页面使用 IGSIL，作者仓库和预印本使用 CoSIL；这两个名称指同一项工作。论文和资源见 [ASE 会议页面](https://conf.researchr.org/details/ase-2025/ase-2025-papers/110/Issue-Localization-via-LLM-Driven-Iterative-Code-Graph-Searching)、[作者仓库](https://github.com/ZhonghaoJiang/CoSIL)及 [预印本 v3](https://arxiv.org/html/2503.22424v3)。

## 当前实现及其边界

固定作者仓库 commit `0568e423735b399d5b089996961fea9ae142e4c7`，调用其 `CoSIL.file_localize_with_g`：依据缺陷正文和项目文件结构生成候选，再收集候选文件的 import 信息，按作者提示进行图上下文反思与文件排序。源码快照来自现有修复前 SHA，目录结构和 Python 文件由作者 `parse_python_file` 解析，避免作者脚本对工作区执行 git checkout 或联网克隆。模型请求适配到本机 OpenAI 兼容服务，保留作者提示词、顺序和文件定位阶段；每次请求及回复单独记录。

**这是作者文件级定位阶段，不是完整的文件＋函数级 IGSIL 流程。** 作者程序默认从文件级输出再进入函数级定位；当前项目目标是文件级排名，因此不运行函数级搜索，也不将文件级结果称为完整端到端复现。不得把此路线与论文函数级结果直接比较。

| 项目 | 本实验设置及与作者差别 |
| --- | --- |
| 模型 | 本地 Qwen2.5-Coder-7B-Instruct，Q4_K_M GGUF；作者论文也有 7B 实验，但原文描述 vLLM 本地部署，当前量化及 llama.cpp 后端不同 |
| 推理资源 | 物理 GPU 1，`CUDA_VISIBLE_DEVICES=1`，服务监听 `127.0.0.1:8098`；32,768 上下文，每次输出最多 2,048 token，seed 42；超过上下文或输出截断记失败 |
| 样本 | 默认 Requests 的 3 条功能检查；500 条固定清单与项目现有对照相同，SWE 格式化版仅 body，使用修复前 SHA |
| 候选文件 | 共用项目 `.py` 候选与排除规则，保留测试文件；作者 `CoSIL_localize_file.py` 会额外过滤测试文件，本实验为统一候选而未应用该过滤 |
| 输出 | 作者文件级提示要求按相关性输出前 5 个文件；保留实际输出顺序，去重、验证路径且最多 5 项，不补造至 10 项。MAP@10、MRR@10、Top-10 对该方法基于最多 5 项；Top-10 必然等于 Top-5，不能将它理解为已经检索了 10 个文件 |
| 失败 | 只在合法路径、非空排名和模型正常完成时标成功；格式错误、截断、超上下文或服务错误均保存原因并按 0 计入主分母 |
| 许可证 | 作者仓库源码公开，但本轮未发现明确 LICENSE；不能将其标记成许可已核实的完全开源实现。模型和依赖许可单独核查 |

当前模型每次请求的输入、输出、token 用量及耗时保存在 `call_*.json`；`author.log` 保存作者阶段记录，`result.json` 保存正文、候选文件哈希、标签、原始顺序和指标。标签只在模型定位完成后用于评价，不传入提示或筛选候选。原始测试文件也保持在共同候选中，不依据答案修改范围。
