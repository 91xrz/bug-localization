# 切块实验结论

截至 2026-11-09 的已记录结果；2026-11-11 清理历史实验文件后集中保留。

**继续使用 AST64 作为默认语义检索基线。** token/DP 切块、局部上下文、作用域边界、语句重叠和调用依赖拼接均未显示稳定收益，不作为已验证的改进方法。AST96 仅用于既有对照，不是已证实的全局最优。

下面各表分别比较同批报告、查询、候选与修复前快照，使用 Qwen3-Embedding-0.6B、512-token 总输入、Max 文件聚合和 @10 指标，无融合。AST64/96 分别表示前缀上限 64/96 tokens，字符预算均为 1500。不同日期和设备的结果不可混为一次实验；Requests 44 条已被反复观察，不是独立留出测试集。

## AST 参数探索：Requests 44 条（2026-10-25）

| 字符预算 / 前缀 tokens | MAP@10 | MRR@10 |
| --- | ---: | ---: |
| 1000 / 64 | 0.5526 | 0.5853 |

| 1500 / 64 | 0.6297 | 0.6526 |
| 1500 / 96 | 0.6351 | 0.6636 |

每组均 44/44 成功。AST96 相对 AST64 的逐报告 AP 为 1 胜、42 平、1 负，MAP 差值的描述性配对 bootstrap 95% 区间为 [−0.000947, 0.017045]，包含 0。前缀预算还会影响超长正文的拆分边界，不能把变化全部归因于前缀内容。默认仍保留 AST64；现有报告多视角流程使用的 AST96 配置保存在 `configs/retrieval/ast96.json`。

## Token 预算与动态规划：Requests 44 条（2026-10-25）

| 路线 | MAP@10 | MRR@10 | Top-1 | Top-10 |
| --- | ---: | ---: | ---: | ---: |
| 原 AST64 | 0.6297 | 0.6526 | 21/44 | 42/44 |
| Token 贪心 | 0.5495 | 0.5600 | 16/44 | 43/44 |
| Token DP | 0.5210 | 0.5348 | 14/44 | 43/44 |

各路线均 44/44 成功。贪心和 DP 相对 AST 的 AP 胜/平/负分别为 12/18/14、9/18/17；MAP 差值分别为 −0.0802、−0.1086，描述性 bootstrap 95% 区间分别为 [−0.1579, −0.0090]、[−0.1859, −0.0395]。Top-10 的少量增加未抵消前排质量下降。

两条新路线的块实例数约为原 AST 的 1.84 倍，约 87%–88% 的块先达到 32 原子候选窗口上限，输入 token 中位数仅约 187；观察到明显碎片化，但未经消融，不能将全部退化归因于此。DP 的结构代价更低也没有带来更好的定位结果。缓存预热不同，历史耗时不构成公平冷启动比较。

## 调用依赖拼接：Requests 44 条（2026-10-26）

两路各 44/44 成功。AP 为 6 胜、30 平、8 负；MAP 差值 −0.0332，描述性 bootstrap 95% 区间 [−0.0843, 0.0097]。15.61% 的块实际增加上下文，追加内容最多 128 tokens，总输入仍为 512；只实现 Python 静态解析。

逐例观察到原匹配被附加内容稀释，以及调用者携带被调用者内容后产生误匹配；这只是对当前实现的诊断，不能推断所有依赖建模都无效。本版本不足以替换原 AST96。
