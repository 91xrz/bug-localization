# AST96 的直接调用依赖上下文实验

## 实验前固定方案（2026-10-26）

以原 `blagent_ast` 的 AST96 为对照，新增独立路线 `ast_dependency`。不更改原 AST 的 1500 字符预算、512 总 tokens、96 前缀 tokens、块边界、源码覆盖、查询文本、模型、Max 聚合或 @10 评价。两个路线使用同一份修复前源码、候选与报告清单；不启用 RRF。

依赖增强只接收源码，不接收 Bug Report 或真实缺陷标签。原块 `code` 和结构前缀完整保留，仅在 `embedding_text` 后追加可容纳的来源明确的上下文；块仍归属于原文件，不归属于被调用文件。不会生成额外的依赖检索块。

| 参数 | 本轮固定值 |
| --- | ---: |
| `dependency_max_functions` | 2 |
| `dependency_max_tokens` | 128，所有附加内容的合计上限 |
| `dependency_function_max_tokens` | 每个函数预览最多64，包括来源标签 |
| `dependency_field_max_tokens` | 所有字段片段合计最多24 |
| `dependency_max_fields` | 最多3个字段 |
| 总输入 / 原结构前缀 | 512 / 96 |

函数数参数最多支持3，本轮仅测试固定值2，不按本轮评价结果追加参数搜索。达到上限或无剩余 token 空间时，保留原块，不截断原正文以腾出空间。每个拼接候选都核对实际 tokenizer 总长度与附加上下文长度。

长依赖函数不能保证完整放入：先尝试完整函数，否则保留实际函数头与可容纳的连续完整顶层语句；长文档字符串不硬截为虚构代码。预览不足时会省略函数体，`preview_truncated` 明确记录。完整函数的文件、修复前源码哈希、限定名称、字节和行范围都保留为引用。

## 静态解析范围

本次44条均来自 Python 项目 requests，依赖解析先可靠实现 Python；原 AST 的多语言切块能力继续保留，其他语言暂时不添加依赖上下文，不能据此声称已完成多语言调用分析。

- 使用 Python 标准库 `ast` 读取源码，**不导入或执行仓库代码**，不新增第三方依赖。
- 识别同模块/闭包中的唯一函数绑定、同类的 `self/cls` 方法、唯一可解析的单继承方法，以及显式 import/相对 import/别名/re-export 指向的仓库内函数。
- 收集原块实际调用的函数，排除自身递归与原块已包含的函数；每个目标只选一次，重复调用只作为选择时的来源计数。
- 优先显式接收者方法，再同文件、再导入函数；同组按原块调用次数降序、首次调用位置、目标标识排序。所有规则在检索指标前确定，不使用查询相关性或标签。
- 字段上下文仅引用本类字段赋值和 `__init__` 中可识别的 `self` 字段初始化，按源码顺序选择，实际代码与来源范围可追踪；不推断运行时字段值。
- 未知对象、参数/局部变量遮蔽、同名多定义、通配符 import、未知装饰器、多继承歧义、外部包与未知父类不猜测目标。`super()` 和实例变量类型推断未实现。
- 这是保守的静态源码绑定，不保证 Python 动态分派后的实际运行时目标。语法不兼容标准库 AST 时仍保留原 Tree-sitter 切块，并记录依赖解析不支持。

## 接入与缓存

实现集中在 `src/bug_localization/dependency_context.py`；语义入口仅增加路线注册、该路线的整份快照准备与统计记录。原切块器、编码器、检索和指标函数保持原样。默认四路配置不改变。

依赖缓存包含整份候选源码清单、Python 版本、模型身份、原 AST 指纹、依赖参数及实现哈希。即使调用者源码未改，只要依赖文件变化，也会生成新的增强缓存/ES 身份，避免跨提交错误复用。没有新增内容的块仍能复用按实际文本内容寻址的向量缓存。

输出 `ast_dependency_chunks.json` 中保存原块标识、附加文本及 token 数、实际函数预览/字段来源、解析状态、未解析调用数量与预算跳过原因。原始 `code` 仍能按顺序重建完整文件。

## 测试与运行

76项单元测试通过，包括名称遮蔽、显式导入/相对导入/别名/re-export、循环导入、单继承、未知接收者、多继承歧义、递归、字段来源、函数上限、原文保留、零预算对照、总长度限制、长方法预览缩进、依赖文件变化触发缓存失效及旧路线身份/输出保持不变。七条路线的10文件多语言 ES 冒烟验证也通过；这只验证切块和检索接入，非 Python 依赖解析仍未实现。

## 44条真实实验结果（2026-10-26）

结果目录：`results/vector/batches/swe_bench_formatted_test_20261026_111653_712367`。两路各44/44成功，使用同一份原44条 requests 清单。主要结果使用预先固定的 Max 聚合：

| 路线 | MAP@10 | MRR@10 | Top-1 | Top-5 | Top-10 | MeanRecall@10 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 原 AST96 | 0.6351 | 0.6636 | 22/44（50.00%） | 38/44（86.36%） | 42/44（95.45%） | 0.9418 |
| AST96 + 最多2个调用依赖 | 0.6019 | 0.6270 | 18/44（40.91%） | 40/44（90.91%） | 42/44（95.45%） | 0.9328 |

MAP 下降0.0332，MRR下降0.0366。按每条报告的 AP 比较，6条改善、30条不变、8条下降。Top-5 多命中2条，但首位命中少4条；本轮不支持用直接拼接依赖替换原 AST96。

次要聚合结果同样保留，不依据测试结果改选主指标或聚合方法：

| 聚合 | 原 AST96 MAP@10 / MRR@10 | 依赖增强 MAP@10 / MRR@10 |
| --- | ---: | ---: |
| Top-3 Mean | 0.6132 / 0.6504 | 0.6113 / 0.6404 |
| Normalized LogSumExp | 0.3577 / 0.4084 | 0.3611 / 0.4077 |

以报告为单位配对 bootstrap（20,000次、seed=20261026），MAP差值的95%区间为[-0.0843, 0.0097]，MRR为[-0.0908, 0.0094]。这些报告共享项目和部分源码快照，且此前已经观察过，因此区间只用于描述，不作为独立留出集上的显著性结论。

### 来源与对照审计

- 62,610个块实例的原正文、前缀与边界均保持不变；9,774个（15.61%）实际增加上下文。计数跨报告累计，包含重复快照。
- 12,990个函数预览、5,001个字段片段均能追溯到对应修复前快照的实际源码位置与哈希；7,562个函数预览来自其他文件。
- 8,968个函数预览为截短预览（69.04%）。因此本实验测试的是有限预算的函数上下文，不是完整依赖函数展开。
- 附加内容最多128 tokens，总输入最多512 tokens，每块最多2个函数；增强块平均增加66.51 tokens。
- 634个块实例对应的源码不兼容当前 Python AST 语法，按设计保留原切块。未解析调用不猜测目标。
- 原 AST96 的44条完整文件排名和指标均与历史批次一致。ES 与本地向量计算的最大余弦误差约2.28e-7。

来源审计验证引用真实存在，不等价于证明 Python 运行时的动态调用目标一定相同。

### 为什么这版没有提升

逐例观察到两类变化，不能据此推断所有依赖增强都无效：

- requests #1888：正确文件 `sessions.py` 的最佳块加入真实 `requote_uri` 函数后，相似度从0.6463降到0.6335，文件从第1降到第3。说明合并到同一向量可能稀释原块与报告的匹配。
- requests #1962：正确文件 `sessions.py` 从第1降到第2；测试文件追加它实际调用的函数预览后升到第1。#3738也出现测试文件超过正确文件的情况。调用者携带被调用者内容，可能增加调用者文件的误匹配。
- 也有改善：#1376正确文件从第4升到第2，#2674从第7升到第3。提升尚不足以抵消退化。

仍保持原 AST96 为对照候选，依赖增强以独立实验路线保留。后续若研究依赖信号，应单独验证如何避免干扰原块表示，并在独立数据上评估；本轮不继续围绕已观察的44条搜索参数，也不将该版本作为已经有效的创新模块。
