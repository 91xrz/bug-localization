# C 重排器第二轮：按基座误判选择训练负例

本轮比较两个问题：同样的微调预算，基座打分挖出的困难未改文件是否优于第一轮的词法负例；最终适配器在实际 C3 流程中是否优于不训练的基座。第一轮结论见[原报告](c-lora-round1.md)。默认 C3 不会因验证集分数提高而自动更改。

## 冻结的设计

- **训练**：复用相同顺序的 BeetleBox 160 份报告、相同的 260 个修复文件及其证据、完全相同的 LocalStack 32 条验证。保留现有词法预选范围（每份报告最多 18 个非标注文件），用原 Qwen3-Reranker-0.6B 对其中的修复前代码块打分，取文件最大分，把前 4 个未改文件送入训练。未标注不等于不相关；严格高于至少一个正例才记作实际反超，不将满四个的补足项也叫作误判。**这是受限候选池挖掘，不是对训练仓库运行完整 A+B+C。**
- **对照**：原 C3、不改的第一轮 LoRA（词法负例）、第二轮 LoRA（模型挖掘）。第二轮从同一未微调基座重新初始化，不在第一轮权重上续训。训练代码、随机种子 20261120、Q/V LoRA rank=8、alpha=16、学习率 5e-5、每四报告更新一次、固定两轮共 80 步。评测相同查询、至多 50 个候选、每文件至多 3 个原 C3 代码块、Max 聚合与同分规则。
- **SWE 主测试**：在历史开发 500 中排除 development45、confirmation90 和第一轮 SWE90，剩余 275 条。固定种子按身份从九项目各取 10 条；未复用上一轮的测试报告，不称全新盲测。比较配对 MAP@10、项目内重采样 95% 区间、Top-1 的找回/丢失数；失败不剔除。另列同批本地 BLAgent 8B 结果，不等于论文原设定。
- **次要方案**：考虑适配器引入原本没有的首位错误。在单独的历史 development45 的真实文件池上，为文件分数 `(1-w)*base + w*new` 从 `0, 0.25, 0.5, 1` 选系数。规则为最多丢一条原先正确的首位，且找回不少于丢失，再最大化开发 MAP，同分取较小 w。保留 w=0 代表拒用适配器。读取新测试表现前冻结选择，主比较始终为未插值原始权重。0<w<1 需要两套文件分数，不等同于一次推理或直接按比例缩放 LoRA 权重。
- **外部复核**：在既有 LCA47（45 项目）上复用冻结输入、同设备原 C3 与旧 LoRA 分数，重算新模型。它已用于第一轮诊断，不能算新的盲测；不用于选轮次或插值系数，不与 SWE 合并。

## 负例是否更难

两轮各有 640 个负例名额。扩展池实际有 3,103 个文件、4,969 个块；新旧负例有 398 个名额被替换，涉及 155/160 条报告。原基座把未改文件排在**至少一个**修复文件前面的数目从 173/640 增至 299/640，排在**全部**修复文件前面的数目从 91 增至 192。107/160 条至少有一个真正反超的负例，但只有 53 条能集齐 4 个。这说明挖掘确实增加了排序难度，并不意味着测试表现一定会改善。

## 结果（2026-11-20）

**不替换原 C3。** 新旧 LoRA 在独立于上一轮的同一批 SWE 报告上重测；不要拿这批绝对值与上一轮另一组 90 条的绝对值做差。三组均 90/90 成功，基座的 12,390 个块分数和完整文件排序均复现。

| SWE 90 | MAP@10 | MRR@10 | Top-1 | Top-10 |
|---|---:|---:|---:|---:|
| 原 C3 | 0.646790 | 0.715970 | 51/90 | 86/90 |
| 第一轮 LoRA | 0.624206 | 0.690648 | 49/90 | 86/90 |
| 第二轮 LoRA | 0.630111 | 0.680556 | 48/90 | 84/90 |
| 次要：开发集选择的 0.5 分数插值 | 0.641082 | 0.706389 | 48/90 | 87/90 |
| 本地 BLAgent 8B | 0.774953 | 0.842901 | 69/90 | 86/90 |

- **挖负例的作用**：第二轮相对第一轮的配对 ΔMAP 为 +0.005905，项目内重采样 95% 区间 [−0.030766,+0.043764]，19 胜、55 平、16 负，不能确立稳定改进。相对原 C3 为 −0.016679 [−0.065520,+0.031509]；找回 8 个正确首位，另丢 11 个首位。
- **区分文件与排好头部不是一回事**：LocalStack 抽样验证的基座/第一轮/第二轮 MAP 为 0.470366 / 0.497950 / 0.533022，正负对胜率为 64.78% / 70.51% / 73.50%。SWE 的 89 条可比较报告有 635 个固定正负对：每个候选内修复文件对比重排前靠前的 5 个未改文件。三个模型的胜率分别是 82.57% / 83.91% / 84.12%。事后逐例核查 11 个丢失的首位：替代正确文件的均不符合既定测试路径规则。例如 sklearn #25232 中，未修改的 `sklearn/impute/_base.py` 顶替了标注的 `sklearn/impute/_iterative.py`。不能简单归因为“把测试文件排前”。
- **开发集保护策略**：w=0.5 在 development45 上的 MAP 为 0.684608（原 0.641878），找回 3 个首位且未丢失。冻结后在 SWE90 上 ΔMAP −0.005708 [−0.034829,+0.023159]，找回 3 个首位却丢失 6 个。它缩小了与基座的差距，但开发集的保护效果没有迁移。
- **LCA47**：基座/第一轮/第二轮 MAP 0.574786 / 0.609943 / 0.613322，Top-1 32 / 32 / 33。第二轮相对第一轮 +0.003379，整项目重采样 95% 区间 [−0.021709,+0.029039]；相对基座 +0.038535 [−0.010500,+0.091469]。46 条可比较报告的正负对胜率 73.51% / 75.36% / 77.14%。冻结插值在这里为 0.601299，不改变结论。

## 下一步与复现

仅增加受限词法池的负例难度，没有解决实际候选中的头部排序。后续优先改变**训练候选来源与训练目标**：在训练集构造真实 C3 候选，按同报告取多个最靠前的竞争实现，优化前几名的相对顺序，同时检测原本正确的首位是否被破坏。至少保留不使用这一目标的同数据对照。不要用本轮 SWE90 或 LCA47 选参。本地嵌入预热记录中，这 160 份训练报告有 51 个已完成的快照（均为 Airflow）；它们适合做计算链路试验，不是均衡的训练池或已经生成的完整 C3 排名。

主要入口：`mine_c_lora_round2.py`（准备/挖掘，CPU/GPU），`train_c_lora.py --data results/c_lora/round2/data --output results/c_lora/round2/training`（同一训练器），`evaluate_c_lora_round2.py`（prepare、base、lexical、hard、summarize），`c_lora_round2_anchor.py`（prepare、calibrate、evaluate），`evaluate_c_lora_round2_lca.py`（外部诊断）。上述入口均位于 `scripts/experiments/`；新的运行使用新输出目录，不覆盖冻结产物。
