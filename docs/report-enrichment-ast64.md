# OB / EB / S2R 报告增强：AST64 探索实验

使用 Requests 44 条探索集。生成器只读取 SWE 格式化数据的 `body`，不读取独立标题、修复补丁、真实文件、候选源码或检索结果。使用本地 Qwen3-8B、BF16、greedy、关闭 thinking，单份报告最多输入 12000 tokens、输出 1536 tokens；超限明确失败，不静默截断。模型文件哈希与运行库版本写入生成缓存身份。

生成 OB（实际行为）、EB（期望行为）、S2R（复现步骤），每项记录描述、逐字证据与 explicit / inferred / missing 标记。允许从报告上下文谨慎推断 EB 和 S2R，不允许推断 OB 或凭空创造命令、环境、标识符。证据必须在报告中逐字存在；此校验不保证推断正确或语义蕴含关系成立，需人工复核。保留第一次原始响应，失败不通过重复生成挑选；缺失字段保持空字符串。生成冒烟中发现非逐字证据，检索前固定离线过滤规则：整个不合格字段剔除并记录原因，不修复引文、不重新请求模型。JSON 结构错误或截断时将该报告所有增强字段置空，并记录 generation_error；保留原文通道和完整评价分母。

代码切块固定 AST64：1500 字符预算、64 tokens 结构前缀、512 tokens 总输入。Embedding 使用现有 Qwen3-Embedding-0.6B；Max 文件聚合、精确语义检索、现有 @10 评价。查询实际输入和截断记录在每个 retrieval 文件的 query_info 中。

运行前固定比较：

- 原报告 q0。
- OB、EB、S2R 的全部七种非空字段组合。
- 仅 explicit 字段。
- 原文在前／增强在前的两种拼接；共同受 512 token 编码限制。
- 原文与 OB+EB+S2R 的完整文件排名 RRF：原文权重 1，增强权重 0.25、0.5、1、2，常数 10、30、60，共 12 组。

空查询为空排名，融合贡献为零。检索失败采用所有路线同一失败分母，不删除报告。缺少首次响应缓存时阻止整批检索；已有响应的生成质量失败按上述空字段规则处理。此网格在探索集上比较，最佳参数不是独立测试成绩；后续应冻结参数并用未参与调节的项目验证。

```bash
.venv/bin/python -B -u scripts/retrieval/run_report_enrichment.py --prepare
# 生成进程结束后，显存释放；已有 ES 保持运行
```

44 份样本产物按样本计共 30,751 输入 tokens、11,357 输出 tokens；其中两条报告正文相同并复用缓存，实际 43 次唯一生成共 30,419 输入 tokens、11,066 输出 tokens。1 份含非法 JSON 转义，整份增强置空；其余响应共剔除 46 个不合格字段，全部保留原始响应及原因。最终 6 份报告的增强全部为空。未重新请求模型，也未依据检索指标筛选生成结果。首次准备批次按严格校验标记失败；检索批次从同一缓存应用上述离线过滤规则，因此准备日志中的失败不代表重新生成或删掉报告。

仅在增强非空的同一 38 条上，原文 MAP 为 0.6126，OB+EB+S2R 为 0.5013；这只是辅助诊断，主结果仍以 44 条为分母。空字段不能完全解释下降。仅 explicit 字段的 MAP 为 0.4314，与包含谨慎推断的 0.4329 很接近；本轮真正保留的推断内容很少，不能据此否定补全方法本身。

原文 17/44 条在 512-token 输入处截断，两种拼接各 18/44 条截断；增强单独查询无截断。原文在前时，长报告后的增强内容可能无法进入编码器，其接近原文的结果不代表增强被充分使用。

目前主要瓶颈是生成质量及报告信息损失；不建议继续在这 44 条上扩大融合网格来寻找微小增益。下一轮应先改善证据约束和字段保留质量，再固定方案做跨项目验证。
